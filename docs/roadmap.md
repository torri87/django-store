# Roadmap

Дорожня карта проєкту «Online Store API» на 4 тижні.

## Тиждень 1. Підготовка проєкту та база даних

**Мета:** налаштувати основу проєкту та спроєктувати модель даних.

- Репозиторій на GitHub, структура `docs/`, робота через гілки та pull requests
- Проєкт Django + Django REST Framework, віртуальне оточення, залежності у `requirements.txt`
- Підключення PostgreSQL, конфігурація через змінні оточення (`.env`, `.env.example`)
- Проєктування схеми бази даних: категорії, товари, користувачі, замовлення, позиції замовлення
- Власна модель користувача, моделі, міграції, реєстрація моделей в адмін-панелі
- Наповнення бази тестовими даними

**Результат:** проєкт запускається, база створена, дані видно в адмін-панелі.

## Тиждень 2. Каталог товарів (перший endpoint)

**Мета:** відкрити публічний доступ до каталогу.

- Ендпоїнти `GET /api/products/`, `GET /api/products/{id}/`, `GET /api/categories/`
- Серіалізатори, ViewSet, роутер
- Фільтр за категорією, пошук за назвою, сортування за ціною та датою
- Інтерактивна документація API (Swagger)
- Перші автотести каталогу

**Результат:** працює публічний каталог із фільтрами, пошуком і документацією.

## Тиждень 3. Базова авторизація

**Мета:** дати користувачам змогу реєструватися та входити.

- Реєстрація користувача, перевірка складності пароля
- Вхід і оновлення токена (JWT)
- Профіль користувача (`/api/auth/me/`): перегляд і редагування власних даних
- Права доступу: захищені ендпоїнти лише для авторизованих, службові поля недоступні для зміни клієнтом
- Тести авторизації

**Результат:** користувачі реєструються, входять і керують профілем.

## Тиждень 4. Замовлення

**Мета:** дати покупцю змогу оформлювати замовлення.

- `POST /api/orders/` зі списком позицій (товар і кількість)
- Ціна позиції та статус визначаються сервером, а не клієнтом
- Перевірка залишків і зменшення їх у транзакції: при помилці замовлення не створюється
- Список і перегляд лише власних замовлень
- Тести замовлень
- Оновлення README та документації

**Результат:** покупець оформлює замовлення та бачить свою історію покупок.

## Після 4 тижнів

- Керування товарами та категоріями через API для адміністратора
- Зображення товарів
- Кошик
- Пагінація списків
- Модулі Payments (оплата) і Notifications (сповіщення)
