\# Інтернет-магазин: REST API

REST API інтернет-магазину на Django та Django REST Framework. Каталог товарів з фільтрами та пошуком, реєстрація й вхід за JWT, оформлення замовлень із перевіркою залишків на складі. Інтерактивна документація доступна через Swagger.

## Стек

- Python
- Django
- Django REST Framework
- PostgreSQL
- JWT-автентифікація (`djangorestframework-simplejwt`)
- Фільтрація та пошук (`django-filter`)
- Документація API (`drf-spectacular`, Swagger UI)

## Можливості

- Каталог товарів і категорій (лише активні товари), фільтр за категорією, пошук за назвою, сортування за ціною та датою додавання
- Реєстрація користувачів, вхід і оновлення токена (JWT)
- Профіль користувача: перегляд і редагування своїх даних (адреса, телефон та ін.)
- Створення замовлення з кількома позиціями: сервер сам визначає ціну та статус, перевіряє залишок і зменшує його
- Користувач бачить лише свої замовлення
- Власна модель користувача (унікальний email, адреса, телефон)
- Автоматична документація API (Swagger)
- Автотести каталогу, авторизації та замовлень

## Запуск через Docker

Потірбен встановлений Docker Desktop.

```bash
cp .env.example .env        # Windows PowerShell: Copy-Item .env.example .env
docker compose up --build
```

В іншому терміналі:

```bash
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
```

Swagger: http://localhost:8000/api/docs/

Зупинити: `docker compose down` (Дані зберігаються).
Зупинити і стерти дані: `docker compose down -v`.

## Документація API

| Адреса | Опис |
|---|---|
| `/api/docs/` | Swagger UI (можна пробувати запити прямо в браузері) |
| `/api/schema/` | Схема OpenAPI |

Щоб перевіряти захищені ендпоїнти у Swagger, отримайте токен через `/api/auth/token/` і натисніть кнопку **Authorize**.

## Ендпоїнти

| Метод | Адреса | Опис | Доступ |
|---|---|---|---|
| GET | `/api/products/` | Список активних товарів | всі |
| GET | `/api/products/{id}/` | Один товар | всі |
| GET | `/api/categories/` | Список категорій | всі |
| GET | `/api/categories/{id}/` | Одна категорія | всі |
| POST | `/api/auth/register/` | Реєстрація | всі |
| POST | `/api/auth/token/` | Вхід, отримання `access` і `refresh` | всі |
| POST | `/api/auth/token/refresh/` | Оновлення `access` токена | всі |
| GET, PATCH | `/api/auth/me/` | Мій профіль | з токеном |
| POST | `/api/orders/` | Створити замовлення | з токеном |
| GET | `/api/orders/` | Список моїх замовлень | з токеном |
| GET | `/api/orders/{id}/` | Одне моє замовлення | з токеном |

### Параметри списку товарів

| Параметр | Приклад | Опис |
|---|---|---|
| `category` | `?category=1` | Фільтр за id категорії |
| `search` | `?search=футболка` | Пошук за назвою |
| `ordering` | `?ordering=-price` | Сортування за `price` або `time_created` (мінус означає за спаданням) |

Параметри можна комбінувати: `/api/products/?category=1&search=фут&ordering=price`.

## Приклади запитів

### Вхід

`POST /api/auth/token/`

```json
{
  "username": "ivan_petrenko",
  "password": "your-password"
}
```

Відповідь:

```json
{
  "refresh": "<refresh-token>",
  "access": "<access-token>"
}
```

### Створення замовлення

`POST /api/orders/` із заголовком `Authorization: Bearer <access-токен>`

```json
{
  "items": [
    {"product": 1, "quantity": 2},
    {"product": 3, "quantity": 1}
  ]
}
```

Відповідь (скорочено):

```json
{
  "id": 5,
  "status": "PENDING",
  "time_created": "2026-10-16T12:00:00+03:00",
  "items": [
    {"product": 1, "quantity": 2, "price": "499.00"},
    {"product": 3, "quantity": 1, "price": "1599.00"}
  ],
  "total": "2597.00"
}
```

Ціну позицій, статус і власника замовлення визначає сервер. Якщо клієнт надішле їх у запиті, значення ігноруються. Якщо товару не вистачає на складі, API повертає `400`, а замовлення не створюється.

## Моделі даних

```
Category 1 ──< Product
User     1 ──< Order
Order    1 ──< OrderItem >── 1 Product
```

- **User**: розширює стандартну модель Django (`AbstractUser`), додає `address`, `phone`, унікальний `email`
- **Category**: назва (унікальна) та опис
- **Product**: категорія, назва, опис, ціна, залишок на складі, ознака активності, час створення
- **Order**: користувач, статус (`PENDING`, `PAID`, `SHIPPED`, `DELIVERED`), час створення
- **OrderItem**: замовлення, товар, кількість, ціна на момент покупки

## Архітектурні рішення

- **Ціна в позиції замовлення зберігається окремо** від ціни товару, тому зміна ціни не змінює старі замовлення.
- **`PROTECT` замість `CASCADE`** для зв'язків з категорією, користувачем і товаром у замовленнях: історія покупок не втрачається при видаленні. Замість видалення товар ховають через `is_active=False`.
- **Створення замовлення виконується в `transaction.atomic()`**: якщо на одному з товарів не вистачає залишку, відкочуються і замовлення, і вже зменшені залишки інших товарів.
- **Сервер не довіряє клієнту:** ціна, статус і власник замовлення задаються на боці сервера, а в серіалізаторах реєстрації та профілю немає службових полів (`is_staff`, `is_superuser`).
- **Ізоляція даних:** у списку замовлень і при перегляді одного замовлення queryset фільтрується за поточним користувачем, тому чужі замовлення недоступні (відповідь `404`). Профіль завжди повертає користувача з токена, а не за `id` в адресі.
- Пароль приймається лише на запис (`write_only`) і зберігається у вигляді хеша.
